# SETRON 포팅 매뉴얼

GitLab 소스를 받아 빌드 · 실행 · 배포하기 위한 문서입니다. SETRON은 **Windows 데스크톱 애플리케이션**이라 웹 서버 · WAS · JVM을 쓰지 않습니다. 화면은 PySide6, 저장은 각 PC의 MySQL 5.6.19, AI는 OpenAI 호환 API를 사용합니다.

## 2. 소스 빌드 · 실행 (개발 PC)

저장소 최상위 폴더의 PowerShell 기준입니다. Git, Python 3.13, uv, Docker Desktop(Linux 엔진 실행 중)이 필요합니다.

### 2-1. 의존성 설치

```powershell
git clone https://lab.ssafy.com/s15-final/S15P31B106.git
cd S15P31B106
uv sync --locked
```

`uv.lock`의 버전으로 `.venv`를 만들고 프로젝트와 개발용 의존성(pytest, PyInstaller)을 설치합니다.

### 2-2. 환경 파일

```powershell
copy .env.example .env
```

`.env`에서 DB 비밀번호 네 개(`SETRON_DB_PASSWORD`, `SETRON_DB_ROOT_PASSWORD`, `SETRON_TEST_DB_PASSWORD`, `SETRON_TEST_DB_ROOT_PASSWORD`)와 AI 키(`SETRON_AI_API_KEY`)를 입력합니다. 비밀번호는 작은따옴표로 감쌉니다(`$` 치환 방지). `.env`는 Git에서 제외됩니다.

### 2-3. MySQL 5.6.19 컨테이너

`mysql:5.6.19` 공식 이미지 태그가 없어 Oracle 보관소의 배포본으로 전용 이미지를 빌드합니다(최초 1회, 인터넷 · 약 306MB).

```powershell
docker compose build mysql-dev
docker compose up -d --wait mysql-dev                     # 개발 DB  (127.0.0.1:13306)
docker compose --profile test up -d --wait mysql-test     # 테스트 DB (127.0.0.1:13307, 테스트할 때만)
```

### 2-4. 스키마 적용 (개발 DB, 최초 1회)

```powershell
docker compose cp ./database/schema_mysql5619.sql mysql-dev:/tmp/schema_mysql5619.sql
docker compose exec mysql-dev mysql --default-character-set=utf8mb4 --user=setron_app --password setron_dev
```

`mysql>`에서 `SOURCE /tmp/schema_mysql5619.sql;` 실행 → 테이블 13개 확인. 테스트 DB에는 직접 적용하지 않습니다(테스트가 자동으로 만듦).

### 2-5. 연결 확인 · 실행 · 테스트

```powershell
uv run --locked --env-file .env python -m setron.infrastructure.database   # DB 연결 확인
uv run --locked --env-file .env python -m setron                           # 앱 실행
uv run --locked --env-file .env python -m pytest -q                        # 자동 테스트 (전체 약 1시간 이상)
```

### 2-6. 시연 데이터 넣기 (선택)

| 대상 | 방법 |
| --- | --- |
| Docker 개발 DB | `prepare_docker_demo_db.bat` (기본 컨테이너 `setron-mysql-dev-1`, 기존 자료가 있으면 확인 후 SQL 백업하고 교체) |
| Windows MySQL | `prepare_demo_db.bat` (`setron.env`의 DB만 관리) |
| 다시 만들기 | `uv run --locked --env-file <설정 파일> python database/reset_demo_db.py --confirm <SETRON_DB_NAME 값>` (관리 테이블 13개를 지우고 스키마 · 시연 자료를 다시 넣음) |

시연 자료: 설비 300대 · 관측 1,800건 · 기준일 6개 · 목표 N 11쌍. 위험 규칙은 넣지 않습니다(시연에서 등록).

## 3. 빌드 시 사용하는 환경 변수

앱은 시작할 때 설정 파일(`--env-file` 또는 실행 파일 옆 `setron.env`)을 읽고, 같은 이름의 Windows 환경 변수가 있으면 그 값을 우선합니다.

| 이름 | 내용 | 개발 기본값 (`.env.example`) |
| --- | --- | --- |
| `SETRON_DB_HOST` · `SETRON_DB_PORT` | MySQL 주소 · 포트 | `127.0.0.1` · `13306` (실사용 보통 `3306`) |
| `SETRON_DB_NAME` · `SETRON_DB_USER` | SETRON용 DB 이름 · 계정 | `setron_dev` · `setron_app` |
| `SETRON_DB_PASSWORD` | 앱 계정 비밀번호 | 각자 입력 |
| `SETRON_DB_CONNECT_TIMEOUT` | 접속 대기(초) | `5` |
| `SETRON_DB_ROOT_PASSWORD` | Docker 컨테이너 root (컨테이너 관리용) | 각자 입력 |
| `SETRON_TEST_DB_*` | 테스트 DB (위와 같은 항목) | `127.0.0.1` · `13307` · `setron_test` · `setron_test` |
| `SETRON_AI_BASE_URL` | OpenAI 호환 API 주소 (`/v1`까지) | `https://gms.ssafy.io/gmsapi/api.openai.com/v1` |
| `SETRON_AI_API_KEY` | API 키 | 각자 발급 (외부서비스.md) |
| `SETRON_AI_MODEL` | 모델 이름 | `.env.example` 값 (사용 가능 모델 확인) |
| `SETRON_AI_TIMEOUT` | AI 응답 대기(초) | `180` (실사용 예시 `60`) |

- `SETRON_AI_*`가 있으면 데이터 가져오기의 AI 추출과 AI 분석이 그 API를 쓰고, 없으면 예제 응답을 씁니다. 다른 `OPENAI_*` 설정이나 기본 OpenAI 서버로 대체하지 않습니다.
- 실제 비밀번호 · 키는 `.env` · `setron.env`에만 보관하고 Git에 올리지 않습니다.

## 4. 배포 (Windows 실행 파일)

### 4-1. 실행 파일 만들기 (인터넷이 되는 개발 PC)

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1
```

빌드 결과는 `dist/SETRON`에 생성됩니다. `SETRON.exe`는 앱 실행 파일이고 `prepare_schema.bat`와 `SETRON_DB_SETUP.exe`는 DB 스키마 설치 도구입니다. 실행 라이브러리와 설정 예시를 포함한 배포 폴더 전체를 압축합니다. 공개 배포본은 빈 출력 폴더에서 새로 빌드합니다.

### 4-2. 사용자 PC 준비

| 항목 | 내용 |
| --- | --- |
| Windows | 10 이상 64비트 |
| Excel | 데스크톱 Excel (가져오기는 열어 둔 Excel 창에서 읽음) |
| MySQL | Windows용 MySQL 5.6.19 실행, SETRON용 빈 DB와 계정(테이블 생성 · 참조, 조회 · 입력 권한) |

### 4-3. 설치 · 실행

1. ZIP을 풀고 폴더 안의 `SETRON.exe`를 실행합니다. DB 설정이 없으면 합성 예시가 나타납니다.
2. 실제 자료를 저장하려면 `setron.env.example`을 같은 폴더에 `setron.env`로 복사해 MySQL 접속 정보를 입력합니다.
3. `prepare_schema.bat`를 실행해 대상 DB를 확인한 뒤 관리 테이블 13개를 생성합니다. 앱을 다시 실행해 연결 상태를 확인합니다.

전체 안내는 [Windows 실행 안내](../docs/windows-package.md)를 참고하세요.

## 5. 배포 시 특이사항

- **폐쇄망 실행**: 실행 파일은 Python · uv 설치 없이 동작합니다. AI는 `setron.env`의 사내 OpenAI 호환 서버 주소 · 키 · 모델만 바꾸면 됩니다.
- **MySQL 5.6.19 기준**: SQL은 5.6.19가 지원하는 기능만 사용. 서버는 `utf8mb4` · `utf8mb4_unicode_ci` · InnoDB, Windows 기본 `lower_case_table_names=1`(테이블 이름이 모두 소문자라 영향 없음).
- **기존 DB 자동 업그레이드**: 앱 시작 시 이미 쓰던 DB에 새 칸(`item.jira_code`, `equipment_snapshot.process_name`)이 없으면 자동으로 추가하고 Jira 값을 원본에서 한 번 채웁니다. 실패해도 앱은 실행됩니다.
- **DB 접속 실패 시**: 합성 예시 자료로 시작하고 상단에 "DB 자료를 읽지 못해…" 안내가 표시됩니다(저장 · 내보내기 제한).
- **SQL 덤프 복원**: 반드시 **빈 DB**에서 실행합니다. 같은 DB에 다시 실행하면 첫 `CREATE TABLE`에서 멈춥니다(자료 변화 없음).
- **PC 간 자료 합치기**: 앱의 데이터 내보내기 → SQL로 받은 파일을 다른 PC의 데이터 가져오기 → SQL에서 미리보기 후 적용합니다.

## 7. DB 덤프 파일 (`exec/setron_db_dump.sql`)

**만들기**: 앱 실행(시연 DB) → **데이터 내보내기 → SQL → SQL 내보내기** → 저장된 `setron_db_<날짜>.sql`을 `setron_db_dump.sql`로 이름을 바꿔 `exec`에 넣습니다. 관리 테이블 13개의 구조와 자료가 모두 들어 있습니다.

**복원** (빈 DB에서):

```powershell
mysql --default-character-set=utf8mb4 -u <계정> -p <빈 DB 이름> < setron_db_dump.sql
```

HeidiSQL에서는 빈 DB를 선택하고 파일을 불러와 실행합니다(9.2에서 확인). 이미 SETRON 테이블이 있는 DB라면 앱의 **데이터 가져오기 → SQL**로 미리보기 후 합칩니다.
